学习日志 · 2026 年 10 月

Created2026-10-01|Updated2026-10-27|学习日志
|Post Views:

这个月从 LVM 的「建卷组 → 建逻辑卷 → 格式化 → 挂载 → 扩容」整条链走通开始，把存储域剩下的两道题往收尾推。新内容在最上面，每条末尾的「能力索引」指向 RHCSA 学习地图。

2026-10-22 星期四

今天把根分区扩了 —— 第一次动 /，不卸载、不重启，df 从 6.2G 变成 11G。反倒是建分区那一步被 parted 绊住：报错里的数字看着像我起点敲错了，其实只是单位换了一把尺子。

今天做了什么

① 根分区扩容：从「盘上还剩 4 GiB」到 df 真的变成 11G

sdc 剩下的空间做成 sdc2（标 lvm）→ pvcreate → vgextend rlm → lvextend -l +100%free /dev/rlm/root → xfs_growfs /。

四层各看一眼，账是通的：vgs 的 VSize 到 10.99g、VFree <4.00g；lvs 的 root 从 <6.20g 变成 10.19g（2609 extents）；df -h / 从 6.2G 变成 11G，used 2.2G / avail 8.1G / 21%。动手前打过快照。

② 四个数字对不上，但每一个都对

  • sdc2 给了 4094MiB，VG 只多出 <4.00g —— PE 是 4 MiB，装不下的余数直接丢掉
  • lvs 说 10.19g，df 说 11G —— df 向上取整到整 G，而且它永远比 lvs 小（XFS 日志 16384 blocks = 64 MiB，再加元数据）
  • parted 报 sdc2 起点差 1 个扇区未对齐 —— 警告不是错误，选 Ignore 继续

这三条要能当场讲出来，不然验收的时候会怀疑自己是不是做错了。

③ 扩容不用改 fstab

/dev/mapper/rlm-root 是稳定名（写在 LVM 元数据里，不随内核 sd 命名漂），文件系统也没重建、UUID 没变。扩容改的是尺寸，不是身份 —— 身份没变就不用动 fstab。

④ 把这几天的存储操作整理成一份手册

存储实操手册：三条路线（裸分区 / LVM / 扩根）对照表 → 每一步的完整命令 → 四层命令对照 → 13 条报错速查 → 26 个可勾选步骤（进度存在浏览器本地）。做这份东西的原因是前面几轮的操作是散的，我要能对着它从头完整走一遍，而不是靠回忆拼。

卡住的地方

一、parted ... 100% 在 GPT 盘上必然报错。

第一眼以为起点错了 —— 4296MB 对不上我要的 4097MiB。其实是十进制 / 二进制：4097 MiB = 4296 MB，8590MB = 8192 MiB，起点终点都没错。真正撞上的是结尾：16777215 是磁盘最后一个扇区，但 GPT 在盘尾留了 33 个扇区（≈17 KiB）放备份分区表 + 备份 GPT 头，分区不能占，可用上界只有 16777182。

所以「到磁盘末尾」在分区的世界里从来不是「到最后一个字节」—— 头尾都得给分区表让位（盘首 34 扇区、盘尾 33 扇区；msdos 只在盘首占 1 个扇区，盘尾没有保留）。稳定写法是结尾直接给具体值。

二、-s 不等于「交互模式但不提问」。

同一条命令，交互模式下 parted 会问 Fix/Ignore/Cancel?，选 Fix 自动收敛到 16777182，分区照样建成；-s 直接报错退出。脚本模式省掉的不只是提问，还有自动修复。 要写进脚本，就得自己先把边界算出来。

三、lvextend 之后 df 不动，这次没被吓到。

昨天是亲眼看到「LV 300m / df 195M」并存的，今天一见 lvs 变了而 df 没变，就知道是少跑了 xfs_growfs，不用怀疑命令没生效。

关键命令或配置

下一步

  1. 题 21（swap）：sdb 还剩 ~7.6 GiB（sdb1 只占 1 GiB）→ 512 MiB swap → 写 fstab → swapon -a 验收 free -h，不动原有 swap
  2. rlm 的 VFree 已经归零，后面再要空间只能从 test VG（还有 3.70g）里挪，或者加盘
  3. 补上一直没做的那个动作：扩容前 dd 造文件 + sha256sum 记下来，扩完 sha256sum -c 对一遍 —— 昨天、今天都是「扩成了但没验内容不丢」

2026-10-21 星期三

隔了将近一个月重新开机，今天只走了两件事：先把打不开的实验机救回来，再把 LVM 从 vgcreate 一路做到「扩到 300 MiB 且 df 真的变大」。题 20 原题算真做成了，但「内容不丢」这一条我自己心里没底 —— 扩之前没留校验文件。

今天做了什么

① 实验机打不开：是锁残留，不是盘坏了

目录里躺着 12 个 .lck，分两批：11 个时间戳全停在 09-17 19:06:45，1 个 .vmx.lck 是今天 09:43。同目录还有两个 .dmp 崩溃转储，.vmx 里 cleanShutdown = "FALSE" —— 指向 09-17 那次非正常关机，锁没被回收。

关键是要分清「锁文件存在」和「有人占用」。两步：① 读 .lck 文件本身，里面写着持有者是哪个 exe；② 去进程列表里对那个 exe 还在不在。09-17 那批写的是虚拟机进程，今天那个写的是图形界面，而当前进程里两个都没有 → 全是孤儿。

处理方式是移走而不是删掉：12 个 .lck 整体移到同目录的备份目录，随时能移回。有快照链的机器，移锁零风险、删盘不可逆 —— 这条记牢。

开机后 lsblk -f / findmnt / pvs / vgs / lvs 和 09-22 收工时一模一样，崩溃没伤到数据层。

② LVM 第二层：建卷组、建逻辑卷

vgcreate test /dev/sdc1 → lvcreate -n vo -L 200MiB test。

这里被卡了一下：我只贴了「命令成功」这一句，vgs / lvs 的输出一个没留。被要求补一次三本账对账 —— pvs 的 PFree、vgs 的 VFree、lvs 的 LSize 要能对上，才算真的建对了。命令返回 created 只说明动作发出去了，不说明账记对了。

③ 格式化 + 挂载 + fstab，四步验收全过

mkfs.xfs 打出三行警告（Filesystem should be larger than 300MB / Log size should be at least 64MB / deprecated）—— 是警告不是失败，200 MiB 的 xfs 照样建成，退出码 0。

验收四步：mount -a 静默无输出、findmnt /vo 的 SOURCE 是 /dev/mapper/test-vo、df -hT 报 195M。

④ 题 20 原题：200 MiB → 300 MiB

lvextend 只改了 LVM 层的账，lvs 已经是 300.00m、Attr 带上 o（open = 正在被使用），但这一瞬间 df 还是 195M —— 两层错位，这次是亲眼看到的，不是背下来的。补一条 xfs_growfs /vo，输出 data blocks changed from 51200 to 76800，df 才变 295M。

from 200.00 MiB (50 extents) to 300.00 MiB (75 extents) 里 50 → 75 正是 PE = 4 MiB 的整数倍换算。

⑤ 顺手把 /dev 认了一遍

/dev 下不是「一堆设备」，是五类东西：真实存储（sda / sda2）、设备映射（dm-0 与 mapper/ 下那堆）、终端（tty*）、伪设备（null / zero / random）、分类索引目录（disk/by-uuid、disk/by-path）。lsblk -o NAME,MAJ:MIN 看主次设备号，ls -l /dev/mapper 看符号链接指向谁 —— /dev/test/vo 和 /dev/mapper/test-vo 其实是同一台设备的两条路径。

卡住的地方

一、只做动作，不留证据。 这次是第三次。vgcreate / lvcreate 都成功，但 vgs / vgdisplay / lvs / lvdisplay 一个都没贴。补完三本账对账才闭环。以后判断一个存储动作做没做成，标准不是「命令没报错」，而是三本账能不能对上。

二、df 为什么比 LV 小一截。 一直以为 200 MiB 就该看到 200M，实际 195M。差分是 xfs 自己的内部日志（1368 blocks × 4 KiB ≈ 5.3 MiB）加上各分配组的元数据 —— 不是「空间丢了」，是文件系统自己要用的。扩到 300 之后同样少 5 MiB，差值基本恒定（200 − 5.3 ≈ 195，300 − 5.3 ≈ 295）。

三、扩容前没留校验文件。 题面要求「保证内容不丢」，我直接扩了。xfs 在线扩容本身是安全的，但没验过就等于没验过。以后的标准动作：扩之前 dd 造一个文件 + sha256sum 记下来，扩完 sha256sum -c 对一遍。

关键命令或配置

下一步

  1. 给根分区扩容（还没做）：sdc 剩下的 ~4 GiB → sdc2（标 lvm）→ pvcreate → vgextend rlm → lvextend -l +100%FREE /dev/rlm/root → xfs_growfs /
  2. 动手前先在 VMware 界面打快照 —— 第一次动根分区，虽然只增不减
  3. 记牢两组区别：-L 4G 是「设成 4G」（绝对值），-l +100%FREE 才是「把卷组剩下的全给它」；xfs_growfs 给挂载点，resize2fs 给设备
  4. 补一个习惯：扩容前先放校验文件，扩完再对
