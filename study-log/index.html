关键判断

这印证了昨天改口后的说法，而且现在能说得更干净：

判据不是「谁先谁后」，而是「这次 chmod 有没有动到组位」。

所以我昨天坚持的「chmod 必须在 setfacl 之前」是错的 —— 错的是写法，不是顺序。我当时做对照实验时换成了数字写法，才撞出问题；参考解给的写法本来就是安全的。

归纳成一句：每条验收命令只验某一层。要验「事情做成了」，就必须真的去做那件事。

二、useradd -p 收的是「已加密的口令」，我传了明文。

结果那个用户的口令字段就是一串明文，等于密码没设 —— 用任何口令都登不进去。而 passwd -S 还报 PS，看着完全正常，只在括号里悄悄写了句「使用了备用认证方案」。正确做法是 passwd <用户> --stdin，或者先加密再传。

三、chmod 2666 里的那个 2 用错了对象。

我本意是「让权限被继承」，那是从协作目录那题借来的思路。但 SGID 只在「目录」上做继承，而且继承的是属组，不是权限位；放在普通文件上毫无作用，只在 ls -l 里多亮一个 S。文件层面要「继承」得用默认 ACL，那是另一种机制，而且也只对目录里新建的东西生效。

四、最有价值的一个坑：不是「顺序不对」，是「两个不同的文件被我当成同一个」。

我做了一个对照实验：先 setfacl 再 chmod 644，发现 natasha 还是能读写，据此断定「必须先 chmod」的说法是错的。实际上当时我手上有两个文件 —— 一个（真正做完的题）mask 是 rw-、能写；另一个（对照实验）mask 被压成了 r--、写不了。我把一个能写的和一个写不了的，当成「同一件事的两次验证」了。

而证明我错了的证据，就印在我自己贴出来的输出里：那两行 user:natasha:rw- #effective:r-- 和 mask::r-- —— 我没读它们，改去看 vim 能不能打开。

今天真正记住的判断

  • 「未验证」比「不会」更危险。 今天三次出错，没有一次是命令敲错，全是验收只做了一半。以后每条验收命令都先问一句：它验的是「配置读通了」，还是「事情做成了」？

  • ACL 的判定是「命中即止」，不是层层叠加。 属主 → 具名用户 → 属组/具名组 → 其他用户，命中第一个就结束。所以「其他用户给了读、但某个具名用户要求不能读」并不矛盾 —— 他在第二步就被截停了，根本走不到最后。

  • mask 是具名条目的天花板。 具名用户的真实权限 = 自己的条目 ∩ mask。

  • chmod 的数字写法一定会重写 mask，符号写法只动你点名的位。 有 ACL 的文件上敲 chmod 644，是把中间那一位数字写进 mask，可能悄悄砍掉具名用户的权限；chmod o=r 只改其他用户，mask 原地不动。我原先说「chmod 必须在 setfacl 之前」太绝对了 —— 真正的判据是 chmod 之后 mask 够不够用。

  • 有扩展 ACL 的文件，ls -l 中间那三位显示的是 mask，不是属组权限。 看着像 664，实际可能完全不是，只看 ls -l 会误判。

  • root 不能当验收工具。 把文件权限设成 000，root 读它照样返回成功（它有 CAP_DAC_OVERRIDE，权限位对它不生效）。必须换一个没有特权的身份去验。

  • 只测相关人员，发现不了「其他用户」配错。 今天有一组数据：把「其他用户」的读权限关掉之后，natasha 和 harry 的结果一点没变，只有换上去的第三个人变了 —— 因为他们两个都在第二步被具名条目截停了。这类错误只能靠第三个人暴露。

  • 「我在 A 上成功了」不能用来否定「B 上失败了」，先确认 A 和 B 的状态是否相同。 这就是我今天明明做对了、却坚持自己有理的根因。

  • 验证只能验证「你已经写出来的东西」，发现不了「你根本不知道要写什么」。 默写 repo 那题，我自己说「比较模糊」的地方，恰好就是漏掉的地方；而我当时想到的验收方式是「用下载判断」，它能检查我写出来的内容，检查不了我没写的字段。

  • 这 9 个领域不是一条线，是三层。 我的排序错在两处，根因是混用了两套标准（前半段按「什么时候用」、后半段按「依赖多深」）：

    1. 环境底座（网络与主机名、软件源、防火墙/SELinux）—— 必须先做，做完就不动
    2. 贯穿工具（基础工具与文本处理、运行中系统、Shell 脚本）—— 没有「学完」这一天，要练到条件反射
    3. 专题模块（用户与组+权限、存储与挂载、容器）—— 可以逐个攻，按分量排队

    只有第 1、3 层适合排序。另外我把「运行中系统」排太后了（它从第 6 题起就全程渗透），把「本地存储」排在了文件系统之后（它其实是挂载和 fstab 的地基）。

  • 学法要改：不按题号走，按能力走。 题库是抽样，能力是全集，把题做完 ≠ 会做，碰到变体照样废。所以现在改成：题面原文贴出来当例子，然后按能力域（系统底座 / 存储挂载 / 用户组权限 / 安全 / 运行中排障 / 文件文本归档 / 容器）一项一项练，每项都要能独立复现、并且自己能验收。

今天做了什么

① 网络专项第一次实操：VMware NAT 改网段之后不通外网

起因是我把实验机的地址从 1 网段改成了 30 网段，结果上不了网。

先搞清了一个本质：NAT 模式下虚拟机连的不是物理网络，而是 VMware 虚拟出来的一台「隐形路由器」（VMnet8）。它有固定的三个约定：

地址 归属
.1 宿主机上的 VMnet8 虚拟网卡
.2 NAT 网关，整个虚拟网络唯一的出口
.128–.254 VMware 自带的 DHCP 地址池

所以改网段相当于把这台路由器搬到了另一个小区 —— 宿主机侧和虚拟机侧必须同时跟上，少一侧就断网。

排查是在宿主机侧直接读权威配置完成的：VMware 的虚拟网络配置是纯文本，就在 C:\ProgramData\VMware\ 下（vmnetnat.conf / vmnetdhcp.conf），比在图形界面里翻要直接。另外宿主机上 arp -a 能一眼看出虚拟机的真实 IP，比进虚拟机敲命令还快。

② 环境初始化收尾

换 yum 源、补齐缺的工具、把 SELinux 和 firewalld 恢复开启、打完 baseline 快照 —— 环境准备这一阶段到此结束。

卡住的地方

一整天都栽在同一种推理上：把「某条 ping 失败」直接等同于「网络坏了」。 一小时内出现了三次：

  1. ping 不通网关 → 以为网关或网络有故障
  2. ping 不通 223.5.5.5 → 以为还是 ping 的问题
  3. ping 不通 114.114.114.114 → 以为 DNS 不通

三次全是误判。要练的判断力是：先问「这条命令到底在测什么」，再问「它失败意味着什么」。

比如 ping 114.114.114.114 —— 它本身就是 IP，这条路根本不查 DNS，失败只说明对方（或出口防火墙）不回应 ICMP；而 ping www.baidu.com 能通，就已经证明 DNS 完全正常了。真正的 DNS 故障长这样，报错出现在解析阶段，根本不会打印出 IP：

几条今天真正记住的判断

  • 网关是谁是「被指定」的，不是靠习惯推出来的。 我下意识觉得网关就是本网段第一个可用地址（.1），但 VMware 把 .1 给了宿主机网卡、.2 给了 NAT 设备。真实网络里网关是谁，只能查设计文档或问规划者。
  • ping 同网段的地址根本不经过网关。 两台同 /24 的机器互 ping 靠的是直接 ARP，路由表和默认网关完全不参与 —— 所以「ping 不通网关」这个说法本身就不准确，它真正的含义是二层 ARP 不通。
  • 双向都不通 = 链路层问题；只有一个方向不通 = 防火墙。 今天宿主机能 ping 通虚拟机、虚拟机 ping 不通宿主机，顺着这条推，问题就在宿主机 Windows 防火墙（VMnet8 被 Windows 归为「公用网络」，默认不响应入站 ping）。这是个假问题，不影响上网，和真问题叠在一起，一开始被混为一谈了。
  • 官方文档也可能是为旧大版本写的。 阿里云镜像页给的命令用的是 Rocky-*.repo，那是 Rocky 8 的命名，在 Rocky 9 上要么完全不生效、要么只静默改一半。照抄任何 glob 之前，先 ls 核对本机真实文件名。
  • setenforce 0 临时判断故障是正常手段，永久 disabled 不是。 一旦 disabled 并重启过，想恢复就得 touch /.autorelabel 做全盘 relabel。幸好我是在重启之前改回来的，一条 setenforce 1 就完事，零副作用 —— 这个「还没重启」的窗口很值钱。
  • 判断「某事有没有做过」，不能只看我以为的那个位置。 比如备份，我以为会在某个目录、没看到就以为没做，实际人家用的是另一个位置。要先搜索，多路径找一遍，再下结论。

2026-09-11 星期五

今天做了什么

把 RHCE 和 CKA 两个证的备考方向定下来了，顺手把能查到的官方大纲核对了一遍，发现三个和网上老攻略不一样的地方。

三个关键发现

  1. RHCE 有前置证书。 可以直接报名 EX294，但红帽规定必须同时持有有效的 RHCSA（EX200）才会授予 RHCE 称号。所以真实路径是 RHCSA → RHCE，跳不过去。
  2. RHCE 新版已经改名并加考。 RHEL 10 版本的官方名称改成了「Red Hat Certified Advanced System Administrator in Ansible」，新增 ansible-navigator、VS Code 工作流、Git 基本操作三项考点。网上大量老资料不覆盖这部分，不能照老攻略学。
  3. RHCE 有个隐藏评分点：配置必须在重启后仍然生效。 服务、挂载、防火墙、用户，只要 reboot 后失效就是零分。这是最高频的失分原因。
