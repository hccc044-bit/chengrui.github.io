学习日志 · 2026 年 11 月

Created2026-11-01|Updated2026-11-03|学习日志
|Post Views:

11 月的主线：把存储域的 swap 收尾，正式转入「软件包与仓库」。这个月开始每个能力域配一本实操手册，随进度长。新内容在最上面，每条末尾的「能力索引」指向 RHCSA 学习地图。

2026-11-03 星期二

今天做了什么

  • 软件包域 P12–P16 一次走完：history undo、versionlock、provides、软件包组、module 流。其中 provides 三条、module 那块（enable → install → list –installed → reset）都对了。
  • 但 versionlock 连着三次实验都不成立，最后干脆自己上机（root 免密）把疑点一个个测掉：锁只作用在求解层、--disableexcludes=all 绕不过去、显式写全 NVRA 也被过滤、对没安装的包执行 add 会把仓库里所有版本一起锁上。
  • 顺手把 rpm 直接操作 P17–P21 在实机上全跑了一遍（rpm -ql/-qc/-qR、rpm -V 三态、rpm2cpio 还原、--test 试穿、卸载边界）。
  • 查了 EX200 考纲原文：rpm -V / rpm2cpio / --nodeps 都不在考纲里，考纲说的「从本地文件系统安装」标准做法是 dnf install /路径/x.rpm。还有一条更要紧的：EX200 现在已经基于 RHEL 10，实验机是 Rocky 9，练手可以，但 dnf5 和 module 的差异要以 RHEL 10 为准。
  • 开新域 systemd：先取基线（get-default = multi-user.target、四个服务全是 enabled+active、multi-user.target.wants/ 里全是符号链接），环境太干净没有现成样本，就用 crond 人为造出「disabled 但 active」的对照，把 mask 的机制测通了。
  • 博客侧：做了「实操手册总览」页，又把手册做成正式文章归到「教程」分类下；顺手修了一处浅色主题下正文发白的问题 —— --light-grey 在 Butterfly 浅色主题里是 #eee，名字像文字色，实际是极浅的描边色。

卡住的地方

  • 第一轮拿 tree 测锁：dnf update tree 输出 Nothing to do.，我以为锁生效了。其实 tree 本来就是仓库里唯一版本 —— 拿一个没有升级路径的包测锁，等于没测。
  • 第二轮我设计「锁前 / 锁后各跑一次 dnf list --upgrades」做对照，实测两次都显示 127。这个对照设计本身是错的，因为 list 走查询层，压根不看锁。
  • dnf history info latest 不报「参数非法」，报 No transaction which manipulates package 'latest' was found —— 那个位置也能被当成包名。正解是 last。
  • rpm2cpio x.rpm | cpio -idmv etc/ssh/sshd_config 少写一个 ./：一个文件都没提取，却照样打印 2992 blocks、退出码 0。
  • rpm -ivh --test /tmp/nonexist.rpm | head 之后 echo $? 是 0，去掉管道才是 1。管道把退出码换成了右边那个命令的。
  • 恢复 sshd_config 的 mtime 手写 20:05:00 不行，真值 20:05:41，最后靠 touch -r 借包内原文件的时间戳才让 rpm -V 彻底无输出。

关键命令或配置

几条今天真正记住的判断

  • 「没报错」和「跑完了」都不是验证。 任何查询类输出（Nothing to do、空列表、0 条结果）都得能回答一句：如果它有东西可做，会显示成什么样？ 答不上来，这条命令就不能当验收。
  • 同一份配置，会被不同层的命令给出不同答案。 判断「是否生效」前先问：这条命令属于哪一层？存储域里是 parted Flags（分区表层）vs blkid（设备签名层）、swap 的类型 GUID vs mkswap 签名；软件包域里是 list / repoquery（查询层）vs update / install（求解层），versionlock 只塞进后者。
  • 命令的语义有一部分写在配置文件里。 clean_requirements_on_remove=True 让 dnf remove htop 把 hwloc-libs 一起清掉，这个场景下 remove 与 undo 结果完全相同。undo 真正不可替代的是三种：升级后能降级、remove 后能装回、一个事务动了 N 个包能整体回退。
  • 「现在跑着吗」和「开机自启吗」是两个独立问题。 is-active 和 is-enabled 各答一个，四种组合都真实存在；enable 的实质就是 wants 目录里那条符号链接。
  • mask 不是「禁止自启」，是「禁止存在」 —— 往 /etc 放一个指向 /dev/null 的空 unit，把 /usr/lib 里的真 unit 盖掉。unit 查找顺序 /etc > /run > /usr/lib。
  • rpm -qc 只列文件级的配置，目录永远不列（所以比 -ql | grep ^/etc 少一行）；一次查多个包时，只要有一个没装，退出码就是 3。

下一步

  • systemd 按依赖顺序走：S1 服务生命周期（样本已经备好）→ S2 target 与默认目标 → S3 journalctl 与日志持久化 → S4 cron / at / timer → S5 chronyd + timedatectl → S6 中断启动取 root。
  • 范围只认考纲：自己写 .service 文件、socket activation、cgroup 原理都标选做，不占主线。

今天的配套手册

  • 软件包实操手册 —— P13 重写了：删掉那个「锁前锁后对比 list」的错误设计，换成「候选存在 + update 不动」的双层判据，并补上 --disableexcludes 绕不过、未安装包 add 是陷阱。
  • 实操手册总览 —— 所有手册的入口和进度都在这一页。
  • 存储手册今天没动。

能力索引 —— 今天涉及的知识点在地图上的位置：

  • 五、软件包与仓库
    • versionlock 对哪个层生效
    • remove 与 undo 到底差在哪
    • rpm -V 九位怎么读、T 为什么消不掉
  • 六、运行中系统与服务
    • mask 是怎么成立的、为什么 unmask 回到 enabled

2026-11-02 星期一

今天做了什么

  • 把存储域最后一块 swap 做完了（分区版全流程）：parted mkpart → partprobe → mkswap → blkid → 写 fstab → swapon -a → 验收。swapon --show 出两行，free -h 的 Swap 从 820M 变成 1.3Gi。还没重启验证，先挂着。
  • 存储手册加了实验 D（swap 分区 + swap 文件，D1–D8）；其中 swap 文件那一步只是写在纸上，本机还没做过。
  • 开了新的能力域：软件包与仓库。先弄清「仓库到底是什么」，再搭一个本地 file:// 仓库，P1–P11 走完。
  • 定下一条规矩：以后每做完一个能力域就配一本 <域>-lab.html，实验用独立小节隔开，随进度长 —— 存储的 A/B/C/D 就是模板。

卡住的地方

  • 以为「把 rpm 放进目录，dnf 就能装」。实际 dnf 只去 <baseurl>/repodata/repomd.xml 取索引，从不扫目录。故意先不跑 createrepo_c 试了一次，makecache 报 Curl error (37): Couldn't read a file:// file，正好对上。单个 rpm 走的是另一条路：dnf install ./x.rpm。
  • 以为 mount -a 会把 swap 也带上。结构上不可能：mount 需要一个挂载点，而 swap 的 fstab 第 2 字段就是 none；内核里是 mount(2) 和 swapon(2) 两条不同的系统调用。
  • .repo 里把 enabled=1 手滑写成 enable=1，dnf 照跑不误 —— 它不校验未知键，而 enabled 默认值就是 1，等于蒙对了。★ 反方向才致命：写 enable=0 想关仓库会静默无效、毫无提示。
  • grep 找 [crb] 那一段：[ 在正则里是字符类起点，必须转义。试了 grep '\$crb\$'、grep '\$crb\$' 全无匹配，最后 grep '\[crb\]' 才对；最省事的是 grep -F '[crb]'。

关键命令或配置

几条今天真正记住的判断

  • swap 有两套互不校验的身份：① 分区表里的类型标记（parted 写的，纯标签，print 的 Flags 列能看到）；② 分区开头约 4 KiB 的签名（mkswap 写，blkid 出 TYPE="swap"）。内核只认 ②，所以「Flags 里标了 swap」不能当验收。
  • swapon --show 里系统盘显示 /dev/dm-1 是内核临时编号，重启可能变 dm-2 —— fstab 绝不能写 dm-N，要写 UUID= 或 /dev/mapper/vg-lv。
  • 只写 fstab、不跑 swapon -a，重启照样生效：开机读 fstab 的不是 swapon 命令，而是 systemd-fstab-generator 把每行翻译成 .swap unit。预演的价值在于把失败挪到有人看着的时候（命令行当场报错 vs 开机静默丢/进 emergency）。
  • dnf install 那两行大小是两层：先 4.3 kB 取 repomd.xml（索引目录），确认变了才拉 44 MB 的全量元数据。所以 clean all 之后必然两行，平时只有第一行才正常。
  • --disablerepo="*" 下装 htop 报 nothing provides libhwloc.so.15，不是本地仓库坏：依赖求解只在「当前启用的仓库集合」里做，hwloc-libs 在 appstream 里被一起关掉了。这条命令只适合证明「某包来自本地仓库」。
  • 仓库跟着文件走，不跟名字走：把 rocky.repo 改名，baseos 和 appstream 一起消失，extras 还在（它住在 rocky-extras.repo）。实测 7 个 .repo 文件 → 48 个仓库定义 → 5 个启用，三个数字互不相等。
  • --enablerepo（只管这一条命令）、--set-enabled（改文件、持久）、--add-repo（写出新文件）三者别混。--set-enabled crb 之后 grep 能看到 enabled 从 0 被改成 1 —— 这就是「临时」和「持久」的实证。

下一步

  • 重启验 swap：free -h + swapon --show；若只剩 820M，先 journalctl -b | grep -i swap。
  • 软件包从 P12 接：dnf history / history undo → dnf provides → versionlock → 组与 module 流 → rpm 直接操作。

今天的配套手册

  • 存储实操手册 —— swap 已补成实验 D（D1–D8），存储域四个实验至此齐全。
  • 软件包实操手册 —— 今天 P1–P11 走的就是这一本：本地 file:// 仓库、依赖跨仓库、--set-enabled 与 --enablerepo 的区别都在里面。
  • 实操手册总览 —— 所有手册的入口和进度，以后从这里进。

能力索引 —— 今天涉及的知识点在地图上的位置：

  • 四、存储与挂载
    • swap 为什么没有 mkfs、也不 mount
    • swap 的两套身份与 dm-N 陷阱
    • 只写 fstab 不 swapon，重启会生效吗
  • 五、软件包与仓库
    • 两行大小是两层下载
    • enabled 写成 enable 为什么静默失效
    • nothing provides 与 provides 的正确写法
